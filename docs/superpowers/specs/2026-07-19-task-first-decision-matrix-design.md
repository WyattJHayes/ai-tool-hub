# AI Tool Hub 任务优先决策矩阵 UI 重排

## 状态与适用范围

本设计于 2026-07-19 经交互式线框评审确认。它覆盖
`docs/superpowers/specs/2026-07-18-editorial-directory-redesign-design.md`
中首页、工具目录和工具详情的布局规定；上一版的中性视觉系统、导航、
页脚、认证、收藏、评分、跟踪和其他路由规定继续有效。

生产实现位于 `next-src`，使用 Next.js 16 App Router、React 18、
TypeScript、Tailwind CSS、Zustand、Supabase 和 Lucide。

## 背景

现有编辑型目录已经去除渐变、粒子和玻璃拟态，但核心发现链路仍以独立卡片为主。
用户可以浏览工具，却难以在同一视线范围内比较“适合什么任务”和“能完成什么”。
工具目录、详情页和全局对比托盘还存在以下具体问题：

- 卡片字段纵向分散，跨工具比较需要反复扫视。
- 首页硬编码场景，和 `scenes.json` 的 canonical 场景存在漂移。
- 目录状态不完整地反映在 URL 中，筛选结果不便分享或刷新恢复。
- 全局对比托盘与移动端底部导航都固定在 `bottom: 0`，可能相互遮挡。
- 任务匹配没有统一派生规则，不能可靠地展示匹配百分比。
- 51 款工具的 `highlights` 仍是通用占位内容，不能直接作为核心能力。

## 目标

将首页、工具目录和工具详情重排为一条任务优先的决策链：

1. 首页帮助用户明确要完成的任务。
2. 工具目录按相同字段横向缩小候选范围。
3. 工具详情提供能力、价格、限制和评价证据，支持最终行动。

首要比较信息是“适用任务 + 核心能力”。价格、来源、平台和更新时间是二级信息。

成功标准：

- 用户无需进入详情即可看到每款工具的适用任务、最多两项核心能力摘要和价格摘要。
- 首页任务入口可直达带可恢复 URL 状态的工具目录。
- 目录明确区分“任务映射”和“同类工具”，不显示虚构匹配分数。
- 用户可选择 2–4 款工具；进入详情并返回后选择保持不变。
- 桌面和移动端均无横向溢出、固定栏遮挡或不可访问的主要操作。

## 非目标

- 不修改 Supabase schema、API 合约或工具 JSON schema。
- 不创建排名、推荐权重或匹配百分比算法。
- 不重设计 `/compare` 页面；仅修正共享对比托盘的显示与入口行为。
- 不重排场景、排行、用户、认证和其他非核心页面。
- 不补写或批量改写现有工具编辑内容。
- 不替换品牌标识或引入新的 UI 组件库。

## 方案选择

### A. 任务矩阵 + 横向比较（采用）

首页选择任务，目录通过紧凑行对齐适用任务、核心能力和价格，详情页承接完整证据。
该方案最直接地支持跨工具判断，代价是目录视觉更接近工作台。

### B. 能力卡片 + 快速预览

保留网格卡片并增加匹配标签和预览抽屉。改动较小、视觉熟悉，但跨卡比较仍需来回扫视。

### C. 工具列表 + 详情分栏

左侧连续选择工具，右侧原位展示详情。桌面浏览效率高，但与独立详情页重复，移动端适配复杂。

## 数据契约

### Canonical 数据源

- 工具、分类和能力内容来自 `next-src/public/data/tools.json`。
- 任务和显式工具映射来自 `next-src/public/data/scenes.json` 的 `scenes[].toolIds`。
- `sceneToolMapping` 的名称映射存在漂移，不参与判断。
- 不读取当前工具记录中缺失的 `Tool.scenes` 或 `Tool.platforms` 字段。

### 适用任务

新增纯函数将场景反向索引为工具任务：

1. 若工具 ID 出现在一个或多个 `scene.toolIds` 中，按 `scenes` 原始顺序展示场景名。
2. 场景名仅做展示标准化，例如移除开头的“我要”。
3. 若工具没有显式场景映射，按 `tool.categories` 顺序展示分类名称，并标记为“同类工具”。
4. 不把场景顺序、分类顺序、`status`、`difficulty` 或 `relatedTools` 当作匹配分数。

选中场景的目录中，任务列始终先显示当前场景名称。工具位于该场景 `toolIds` 时标记
“任务映射”，仅通过固定分类映射进入时标记“同类工具”；其他显式任务以 `+N` 提示。
没有选中场景时才直接使用上面的通用展示任务规则。

现有数据中 31/83 款工具有显式场景映射，其余 52 款使用分类回退。

选中任务后，目录分为两个有标题的组：

- “任务匹配”：`tool.id` 位于该场景的 `toolIds` 中。
- “同类工具”：不在显式映射中，但属于该场景对应的分类。

场景到同类分类的固定映射为：

| 场景 | 分类 |
| --- | --- |
| `ppt` | `office`, `design` |
| `coding` | `code` |
| `video` | `video` |
| `drawing` | `painting`, `design` |
| `copywriting` | `writing` |
| `music` | `music` |
| `research` | `search` |
| `agent` | `agent` |

组内默认保持 `tools.json` 的稳定目录顺序；用户选择排序后，两组分别应用同一排序规则。
这是一种分组，不是数值排名。

### 核心能力

能力派生规则必须确定且可单测：

1. 对 `tool.highlights` 去空、去重。
2. 过滤通用占位词：`AI驱动`、`高效便捷`、`持续更新`。
3. 取前两项有效能力作为目录摘要。
4. 若过滤后为空，使用 `tool.desc` 作为一条事实摘要。
5. 详情页可展示全部有效能力；仍为空时只展示简介，不渲染空区块。

已有宣传或 benchmark 文案可以按现有内容原样显示，但不得转化为匹配分数或排名。

### 二级信息

- 价格使用现有 `pricing` 和 `valueTag`，沿用 `getPricingHighlight` 的摘要规则。
- 价格筛选值固定为：`free-tier`（至少一个价格为 0 的方案）、`fully-free`
  （存在方案且全部价格为 0）和 `paid-only`（存在方案且全部价格大于 0）。
  缺少 `pricing` 的工具不匹配任何价格筛选。
- 来源从 `toolTags` 的“国产/海外”派生。
- 平台优先使用实际 `tool.platform`，再把 `toolTags` 中的“网页版”规范为 `web`。
- 平台规范值限定为 `web`、`local`、`cli`、`desktop`；筛选只渲染数据中真实存在的选项，
  不显示空选项。
- 更新时间使用 `updateTime`；缺失时省略，不显示“未知”占位。

### 搜索匹配

搜索对用户可见的事实字段做不区分大小写的包含匹配：工具名、简介、有效核心能力、
展示任务/分类名称和 `toolTags`。查询不产生相关性分数，结果继续使用当前分组和排序规则。
空白查询等同于未搜索。

## 信息架构

### 首页 `/`

首页只负责确定任务和进入发现链路：

1. 保留紧凑的标题、副文和全局搜索。
2. 搜索工具、任务或能力时导航至 `/tools?q=<query>`。
3. 紧接搜索展示 `scenes.json` 的 8 个真实任务入口，不再使用页面内硬编码场景。
4. 任务入口使用开放式两列/四列列表，而非大面积营销卡片。
5. 选择任务导航至 `/tools?scene=<scene-id>`。
6. “本周值得试”保留为任务入口后的辅助发现区，使用紧凑决策行而非现有大卡片。

“本周值得试”沿用当前确定性规则：按源数据顺序取 `status === 'hot'` 的工具；不足 6 款时，
按源数据顺序从其余工具补足至 6 款。该顺序不显示为推荐分数。

首页不恢复数据概览、营销型 Hero、装饰插画或虚构推荐分数。

### 工具目录 `/tools`

目录是核心决策工作台。桌面结构：

1. `TaskContextBar`：搜索框、当前任务菜单、结果数量和排序。
2. `FilterRail`：价格、来源和真实存在的平台选项。
3. `ToolDecisionList`：按“任务匹配/同类工具”分组的对齐列表。
4. `CompareTray`：选择至少 2 款时出现，最多 4 款。

每个 `ToolDecisionRow` 固定字段顺序：

1. 对比复选框。
2. 工具图标、名称、来源和平台。
3. 适用任务及“任务映射/同类工具”来源标签。
4. 最多两项核心能力摘要。
5. 价格摘要。
6. 详情链接。

工具外链不放在矩阵主行中，避免用户在尚未核验证据前误离开目录；外链继续保留在详情页。

有 `scene` 时显示“任务匹配”和“同类工具”两组；没有 `scene` 时，在搜索、分类和二级筛选后
显示一个扁平工具列表。目录行最多显示一个主任务和 `+N` 提示，详情页展示全部任务。

### URL 状态

目录 URL 是筛选状态的可分享来源，支持以下参数：

- `scene`: 单个有效场景 ID。
- `q`: 搜索文本。
- `category`: 单个分类 ID；选择 `scene` 时隐藏但保留有效值会造成歧义，因此设置场景时清除分类。
- `price`: 单个有效价格筛选值：`free-tier`、`fully-free` 或 `paid-only`。
- `origin`: 逗号分隔的 `domestic`、`overseas`。
- `platform`: 逗号分隔的当前数据平台值。
- `sort`: 现有 `SortOption` 中的有效值。

`scene` 与 `category` 互斥：设置场景时清除分类，设置分类时清除场景。解析器遇到两者同时存在时
优先使用有效 `scene` 并忽略 `category`。解析器忽略其他未知值并使用默认状态，不把无效参数写回
URL。首次解析不主动改写含无效值的地址；下一次控件变更只序列化有效参数。`origin` 和
`platform` 各自组内按 OR 组合，不同筛选维度之间按 AND 组合。控件变更使用 `router.replace`，
进入详情使用 `router.push`。浏览器前进/后退必须恢复界面。

### 工具详情 `/tools/[slug]`

详情页首屏先给决策摘要，再提供完整证据：

1. 顶部摘要包含名称、简介、适用任务、最多两项核心能力摘要和价格摘要。
2. 主操作是“访问官网”；收藏和加入比较为次操作。
3. 桌面正文使用主内容 + 文档流内的 `position: sticky` 决策栏；它带导航偏移并在父容器末端停止。
   移动端按同一顺序单列排列。
4. 正文依次展示完整能力、定价与限制、标签/更新信息、评分和用户评价。
5. “替代方案”使用 `ToolDecisionRow` 的紧凑变体，按同任务优先、同类回退；不使用卡片网格。
6. 返回目录时保留 URL 查询和对比选择。

从目录进入详情时，链接添加经过 URL 编码的 `from` 参数，值必须是当前 `/tools` 路径和查询。
详情返回链接只接受精确 `/tools` 或以 `/tools?` 开头的站内 `from`；无效或缺失时回退到 `/tools`。
该参数只负责返回上下文，不参与工具数据查询。

详情不存在时保留现有“工具未找到”行为，并返回工具目录。评分 API 失败只隐藏远端评价，
不阻断静态工具信息和主要操作。

## 组件边界

### 纯数据模块

新增独立纯函数模块，负责：

- 建立场景反向索引。
- 派生展示任务及其来源。
- 派生并过滤核心能力。
- 派生来源、平台和价格摘要。
- 将工具分为任务匹配和同类工具。
- 解析、规范化和序列化目录查询参数。

这些函数不访问 Zustand、Router 或 DOM，可独立单测。

### 页面组件

- `TaskEntryList`: 首页真实任务入口，只依赖场景数据和导航回调。
- `TaskContextBar`: 管理任务、无场景时的分类、搜索、结果数量和排序控件。
- `FilterRail`: 桌面二级筛选；无内部业务状态。
- `MobileFilterDrawer`: 移动端使用同一筛选模型，不复制派生逻辑。
- `ToolDecisionList`: 负责分组标题和行列表。
- `ToolDecisionRow`: 负责一款工具的固定字段与选择操作。
- `ToolDecisionSummary`: 详情首屏摘要，与目录共享派生展示模型。
- `CompareTray`: 由现有全局 `CompareBar` 重构而来，继续读取 `useCompareStore`，修正路由和移动端定位。

现有 `ToolCard` 保留给范围外页面，避免将全站卡片一次性改成矩阵行。
首页、目录和详情替代方案使用新的决策组件。
根布局只挂载一个重构后的 `CompareTray`，不得同时保留旧 `CompareBar`。

## 状态与数据流

1. `useToolStore` 继续负责工具/分类加载、API 到静态 JSON 的降级和点击数据。
2. Store 增加明确的 `error` 和 `retryLoadData`，只有 API 与静态数据都失败时设置错误。
3. `/tools` 不读取 Store 中现有的 `searchTerm`、`selectedCategory`、`sort` 或 `filteredTools`；
   纯选择器只使用原始 `tools`、`categories` 和解析后的 URL 参数生成分组结果。
4. `useCompareStore` 继续跨页面保存 0–4 款选择。
5. 第 5 款工具保持可聚焦，使用 `aria-disabled="true"` 阻止加入，并通过 `aria-live` 解释上限。
6. 对比托盘在 `/compare` 隐藏，避免重复入口。
7. 移动端对比托盘定位在底部导航上方，并为正文增加等量安全区。

比较页面本身继续使用当前数据和布局，不在本设计中改造。

## 视觉系统

延续已经上线的中性编辑视觉：

- 浅色页面 `#F6F7F4`、内容面 `#FFFFFF`、主文字 `#171A17`。
- 品牌强调色 `#176B4D`；红、黄只用于错误和警告。
- 深色主题继续使用中性炭黑/灰和绿色强调色。
- 页面最大宽度 1280px；导航高度 64px。
- 输入、按钮、矩阵行和浮层圆角 6–8px；标签最大 4px。
- 使用本地 Geist 处理西文和数字，中文回退系统字体；字距为 0。
- 主要控件和移动端触控区域至少 44px。
- 页面区块不包装为浮卡，卡片不嵌套；阴影仅用于抽屉和固定托盘。
- 使用 Lucide 图标表达导航和操作，不增加装饰性图标或动画。

## 响应式规则

### 桌面（`>= 1024px`）

- 二级筛选为左侧窄栏，矩阵占据剩余宽度。
- 列宽稳定，能力列最宽，名称和价格不换成纵向卡片。
- 详情页使用主内容 + 文档流内的 sticky 决策栏。

### 平板（`768px–1023px`）

- 筛选栏改为抽屉按钮。
- 矩阵保留名称、任务、能力和价格；来源/平台合并到名称副行。

### 移动（`< 768px`）

- 任务、筛选、排序使用三个稳定宽度的菜单按钮，不使用无提示的横向滚动标签。
- 每个矩阵行变为紧凑纵向条目，但信息顺序不变。
- 对比复选框位于条目右上，详情链接位于底部右侧。
- 对比托盘位于底部导航上方，并考虑 `safe-area-inset-bottom`。
- 320px 宽仍不产生页面级横向滚动。

## 加载、空态与错误处理

- 加载：渲染保持最终列宽/条目高度的骨架，不改变页面节奏。
- 无结果：保留当前任务，只提供“清除二级筛选”和修改搜索；不跳回全目录。
- 数据失败：页面框架和导航保留，显示内联错误及“重试”；不抛出整页错误覆盖层。
- 无任务映射：明确标记“同类工具”，不留空、不显示 0% 匹配。
- 无有效能力：显示真实简介，不显示通用占位能力。
- 选择达到上限：阻止第 5 款加入并解释“最多比较 4 款”。
- 无替代方案：省略替代区块，不渲染空框。
- 无更新时间或平台：省略对应二级字段，不显示占位字符。

## 无障碍

- 任务菜单、筛选抽屉、矩阵复选框、详情链接和对比托盘可用键盘完整操作。
- 每个复选框的无障碍名称包含工具名。
- 分组标题使用语义化标题，矩阵使用列表/描述结构而非无语义 `div` 表格。
- `aria-live` 只播报结果数量、选择上限和加载错误，避免重复播报所有筛选变化。
- 焦点样式沿用全局 2px 绿色轮廓，不用颜色作为唯一状态信号。
- 移动端和桌面端主要操作触控目标不小于 44px。

## 测试策略

### 纯函数单测

- 显式场景任务、多个场景任务和分类回退。
- 通用能力占位过滤、去重和简介回退。
- 场景分组与固定同类分类映射。
- 查询参数解析、未知值忽略、序列化和浏览器恢复。
- 平台与价格摘要的缺失数据行为。

### 组件与契约测试

- `ToolDecisionRow` 字段顺序和任务来源标签。
- 对比选择最多 4 款，第 5 款给出可访问解释。
- `CompareTray` 在 `/compare` 隐藏，在移动端位于底部导航上方。
- 移动端嵌套路由保持正确导航选中状态。
- 加载、无结果、双重数据加载失败和详情不存在状态。

### 浏览器验收

完整路径：

1. 首页选择“我要做调研”。
2. 跳转 `/tools?scene=research`，看到任务匹配和同类工具分组。
3. 搜索或应用二级筛选，刷新后状态保持。
4. 选择 2 款工具，进入其中一款详情后返回，选择仍在。
5. 从对比托盘进入现有比较页，托盘在比较页隐藏。

检查视口：`1440x900`、`1280x720`、`390x844` 和 320px 宽。
