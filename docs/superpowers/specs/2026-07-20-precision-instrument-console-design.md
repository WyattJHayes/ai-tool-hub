# AI Tool Hub 精密仪器控制台设计

## 状态与适用范围

本设计于 2026-07-20 经用户批准，定义 AI Tool Hub 的“精密仪器控制台”视觉方向。
它在现有任务优先产品结构和碳黑主题基础上增强科技感，不改变工具数据、场景数据、
页面文案、字段顺序、搜索逻辑、URL 参数、路由、API 或核心交互。

以下文档继续作为结构、行为和基础主题依据：

- `docs/superpowers/specs/2026-07-19-task-first-decision-matrix-design.md`
- `docs/superpowers/specs/2026-07-20-carbon-console-theme-design.md`

发生冲突时，本规范只覆盖首页与共享组件的视觉编排、首次主题默认值、精密边线、
状态轨道和验收要求。现有碳黑、冷白、青色、橙色风险语义继续有效。

生产实现继续位于 `next-src`，使用现有 Next.js、Tailwind CSS、Geist、Zustand 和 Lucide。
不引入新的组件库、图标库、字体、业务状态或可视化依赖。

## 目标

将当前克制的碳黑目录进一步统一为“精密仪器控制台”：科技感来自稳定的工作面、
精确的 1px keyline、青色交互轨道、严格对齐和明确状态，而不是视觉特效。

成功标准：

- 首页仍然以搜索和任务选择为核心，用户无需重新学习信息架构。
- 首次访问呈现深色控制台主题，已保存的用户主题偏好继续生效。
- 首页、导航、搜索、任务矩阵和推荐决策行属于同一套视觉系统。
- 深色主题使用碳黑、冷白和青色；浅色主题使用冷灰、白色和深青色，不出现灰绿。
- 青色只表达品牌、焦点、选中、链接和主要操作；橙色只表达真实错误与关键风险。
- 320px 至桌面宽度均无横向滚动、遮挡、文本溢出或状态引起的布局位移。

## 非目标

- 不重写首页文案、搜索建议、任务数据或“本周值得试”的选取逻辑。
- 不重排工具目录、详情、比较、场景、排行、用户或认证页面的信息架构。
- 不新增指标、图表、终端日志、活动流、状态读数、标签或营销内容。
- 不增加紫色、绿色、渐变、发光、玻璃拟态、背景网格、扫描线、粒子或 3D 效果。
- 不使用卡片嵌套、浮动大卡片、胶囊化导航或超过 6px 的普通组件圆角。
- 不使用缩放、旋转、弹跳、悬停位移或持续动画模拟科技感。

## 采用方向

### 精密仪器控制台

页面使用连续、全宽的产品工作面。导航、搜索、任务矩阵和推荐列表通过间距、对齐、
单层 keyline 与青色状态轨道分层，不把每个区块包装成独立卡片。

该方向比工业数据舱更轻、更适合高频浏览，也比开放式研究终端更明确地传达科技感。
代价是界面气质更冷、更专业，因此必须控制边线密度，并保持正文和交互目标舒适可读。

## 设计原则

1. **精确而非炫技**：对齐、边线和状态反馈优先于装饰。
2. **任务优先**：搜索和真实任务入口继续占据首屏的主要注意力。
3. **结构连续**：页面是一个连续工作面，不是多个悬浮卡片的集合。
4. **一色一义**：青色表示交互，橙色表示风险，中性色承载内容。
5. **稳定反馈**：任何交互状态都不能改变行高、列宽、按钮尺寸或页面位置。
6. **明暗同构**：浅色与深色共享组件结构、状态和层级，仅替换语义令牌。

## 视觉令牌

实现优先复用现有 CSS 语义变量，不新增任意硬编码色值。

### 深色主题

| 语义 | 现有令牌 | 值 |
| --- | --- | --- |
| 页面 | `--page` | `#080B0E` |
| 工作面 | `--surface` | `#10161A` |
| 次级工作面 | `--surface-subtle` | `#151E23` |
| 默认边线 | `--line` | `#26343B` |
| 强边线 | `--line-strong` | `#58707B` |
| 主文字 | `--ink` | `#E8F7FB` |
| 次文字 | `--muted` | `#A4B8C1` |
| 交互青色 | `--accent` | `#46D9F2` |
| 选中底色 | `--accent-soft` | `#123840` |
| 风险橙色 | `--signal` | `#F28B3C` |

### 浅色主题

浅色继续使用现有冷灰与白色工作面：`#F3F6F8`、`#FFFFFF`、`#EAF0F3`，
交互使用深青色 `#007E99`。不得回退到灰绿、墨绿或带绿色倾向的中性色。

### 材质与几何

- 普通分隔使用 1px `--line`，控件边界和重要分组使用 `--line-strong`。
- 当前项或选中项使用 2px 导航轨道或 3px 内容侧轨，并为轨道预留空间。
- 普通输入、按钮、菜单和工作面使用 6px 圆角；小标签使用 4px。
- 页面主体和内容区不使用阴影；阴影只允许出现在现有菜单、弹窗和固定托盘。
- 仪器刻度式标记只允许出现在桌面区块边界，每个区块最多两处短线标记。
  它们必须由现有边线颜色构成、隐藏于无障碍树，不能重复成背景网格。

## 页面框架

### 全局导航

- 桌面导航高度保持 64px，品牌在左、主导航居中、主题与账户操作在右。
- 当前路由同时使用青色文字和 2px 底部轨道，不使用青色胶囊背景。
- 主题、分享和账户按钮保持 44×44px，使用 Lucide 图标和可访问名称。
- 移动端继续使用现有底部导航，当前项使用图标、文字和顶部/侧部轨道共同表达。

### 首页首要控制区

- 内容宽度继续约束在 1160px，标题、说明和搜索左对齐。
- 标题保持当前 36px 桌面层级，移动端使用既有 30px 层级，不随视口连续缩放。
- 搜索框保持 56px 高，最大宽度约 768px；搜索按钮为青色实底矩形控件。
- 首要控制区不放入卡片，不增加图像、指标、状态读数或装饰背景。

### 任务矩阵

- 保留“你要完成什么？”和 8 个真实任务入口。
- 桌面为 4×2，平板为 2 列，移动端为单列。
- 任务项只显示任务名称、现有说明和右侧 Chevron，不恢复装饰图标。
- 默认状态使用连续网格 keyline；悬停和键盘焦点增加 3px 青色左轨。
- 侧轨、边线和背景变化不得改变任务项宽度、高度或文字位置。

### 本周推荐

- 保留“本周值得试”和现有 6 条工具决策行选择逻辑。
- 推荐区是一个连续列表，不把每个工具包装成独立卡片。
- 桌面稳定展示工具/来源、适用任务、能力、价格和详情入口。
- 移动端按现有字段顺序纵向排列，名称、标签和价格可换行但不能越界。
- 首页继续隐藏比较复选框；点击决策行进入工具详情。

## 组件与交互

### 搜索

- 默认使用工作面、强边线和冷白/深色文字。
- 聚焦使用 2px 青色轮廓和 2px 外偏移，不使用 glow 或尺寸变化。
- 搜索建议保持单层列表；活动项使用 3px 青色侧轨和 `--accent-soft`。
- 保留 Cmd/Ctrl+K、上下键、Enter、Escape、搜索历史和工具建议行为。

### 任务入口与决策行

- 悬停只改变背景、边线、文字或图标颜色，过渡时长为现有 140ms `ease-out`。
- 选中、悬停和焦点必须有不同且可辨识的组合状态。
- 决策行的列宽和响应式字段顺序保持稳定，不通过位置或缩放反馈交互。
- Chevron、搜索、主题、账户等熟悉操作使用 Lucide 图标，不增加文字胶囊按钮。

### 主题

- 新用户和没有持久化主题记录的用户默认进入深色主题。
- 用户已保存的浅色或深色选择优先于默认值，并继续持久化。
- 首次渲染不得出现明显的浅色闪烁；服务端主题元数据与客户端初始状态必须一致。
- 浅色与深色使用相同布局、边线厚度、圆角、交互和可访问状态。

### 加载、空态与错误

- 加载使用静态 `--surface-subtle` 骨架和 keyline，不使用 shimmer 或渐变。
- 空态保留页面结构、真实说明和现有恢复操作，不添加插图占位。
- 错误使用橙色辅助轨、风险文字、警告图标和明确重试操作。
- 加载、已验证为空和失败必须继续以不同文字及控件状态表达。

## 数据与行为边界

- `useToolStore`、`useSceneData`、搜索建议、工具排序和每周推荐逻辑保持不变。
- 场景查询继续跳转到 `/tools?scene=...`，搜索继续跳转到 `/tools?q=...`。
- 工具、场景、评分、收藏、比较和认证 API 合约保持不变。
- 只允许调整主题默认值及与避免主题闪烁直接相关的初始化逻辑。
- 不修改工具 JSON、Supabase 数据、服务端业务规则或统计行为。

## 响应式与无障碍

- 支持至少 `1440×900`、`390×844` 和 `320×844`，并保留现有中间断点。
- 320px 宽不得产生页面级横向滚动；长名称、标签和按钮文字必须安全换行。
- 移动底部导航、比较托盘和安全区继续正确叠放，最后一项内容不得被遮挡。
- 普通文本达到 WCAG AA 4.5:1，非文本控件与焦点边界至少达到 3:1。
- 主要操作、图标按钮和任务入口保持至少 44×44px 交互目标。
- 选中、错误和禁用状态不能只依赖颜色，必须同时使用轨道、边线、图标或文字。
- `prefers-reduced-motion: reduce` 下将非必要过渡降至近零。

## 测试与设计 QA

### 静态与契约检查

- 验证深浅主题令牌、首次深色默认值、持久化优先级和浏览器主题元数据。
- 扫描 `next-src/src`，禁止绿色、紫色、渐变、glow、玻璃、背景网格和大圆角逃逸。
- 验证任务矩阵断点、无首页比较复选框、稳定字段顺序和 44px 交互目标。
- 运行现有主题、任务决策、搜索、数据加载、比较选择和编辑型 UI 契约。

### 浏览器验收

- 深色与浅色分别检查首页、工具目录、详情和比较页面。
- 首页至少覆盖 `1440×900`、`390×844`、`320×844`。
- 验证搜索聚焦与建议、任务跳转、决策行跳转、主题切换和移动底部导航。
- 检查页面非空、文字清晰、边线稳定、无重叠、无裁切、无横向滚动和无布局跳动。
- 对首页修改前后的相同视口截图进行结构对照，确认文案、任务数量、字段和路由未回归。

## 完成定义

- 用户批准的页面框架、组件交互、响应式和验收规则全部实现。
- 浅色与深色主题属于同一套精密仪器控制台系统。
- 首页保持原有任务优先工作流，且科技感不依赖被禁止的视觉特效。
- 静态测试、构建、浏览器守卫和规定视口的设计 QA 全部通过。
- 生产部署后首页返回 HTTP 200，并显示已验证的目标版本。
