# AI Tool Hub 碳黑控制台主题设计

## 状态与适用范围

本设计于 2026-07-20 经用户确认，定义 AI Tool Hub 的全站浅色与深色主题。
它只重新编排视觉主题，不改变已经实现的任务优先信息架构、页面结构、字段顺序、
文案、数据、路由或交互行为。

以下文档继续作为结构和行为依据：

- `docs/superpowers/specs/2026-07-19-task-first-decision-matrix-design.md`
- `docs/superpowers/specs/2026-07-18-editorial-directory-redesign-design.md`

现有评审截图继续作为布局、密度、文案和响应式行为的事实基准，但不再作为颜色或材质基准。
本规范覆盖上述文档及截图中的暖白、灰绿、墨绿和绿色焦点规定。发生冲突时，以本规范为准。

生产实现位于 `next-src`，继续使用现有 Next.js、Tailwind CSS、Geist、Zustand 和 Lucide
技术边界，不引入新的 UI 组件库或图标库。

## 目标

将当前灰绿编辑型目录统一为“碳黑控制台”：以碳黑、冷白和高可读青色形成明确、克制的
科技感，同时保持任务决策工具应有的安静、紧凑和可扫描性。

成功标准：

- 浅色与深色主题属于同一个视觉系统，而不是两套独立皮肤。
- 页面、导航、搜索、筛选、决策行、详情证据区和比较流程使用一致的颜色语义。
- 全站不再出现绿色或带明显绿色倾向的中性色、状态色、焦点色和装饰色。
- 青色只承担品牌、选中、链接、焦点和主要操作语义；橙色只承担警告、错误和关键风险语义。
- 科技感来自精确 keyline、碳黑工具面、紧凑层级和状态反馈，不依赖渐变、发光或装饰网格。
- 保留 44px 触控目标、键盘操作、可见焦点、320px 最小宽度和当前响应式行为。

## 非目标

- 不改变首页、目录、详情、场景、排行、比较、用户或认证页面的信息架构。
- 不改变页面文案、工具数据、字段顺序、筛选规则、URL 状态或 API 合约。
- 不新增统计指标、推荐分数、终端日志、监控图表或其他“科技感”内容。
- 不增加渐变、光晕、玻璃拟态、背景网格、扫描线、粒子、3D 倾斜或持续动画。
- 不把页面区块改成营销卡片，不增加卡片嵌套或装饰性浮层。
- 不替换品牌标识、产品图标、Geist 字体或 Lucide 图标。
- 不重新设计任务优先决策矩阵已经确认的布局和交互。

## 采用方向

### 方向 1：碳黑控制台（采用）

浅色主题使用冷灰页面和白色工作面；深色主题使用近黑页面和碳黑工作面。两者共享青色
交互语义、橙色风险语义、清晰的 1px keyline 和 4–6px 圆角。详情和比较等高判断密度区域
使用更明确的工具面层级，形成控制台感。

该方向比霓虹赛博风更耐久，也比普通黑白后台更有产品识别度。代价是边框、文字和状态色
必须严格使用语义令牌，否则界面容易退化为杂乱的蓝色后台。

## 设计原则

1. **冷静而非炫技**：科技感来自信息精度和交互反馈，不来自装饰特效。
2. **结构先于色彩**：边框、留白、对齐和字重先建立层级，青色不用于填满大面积容器。
3. **一色一义**：青色表示品牌与交互，橙色表示风险；普通信息保持中性。
4. **明暗同构**：相同组件在两种主题中保持相同层级、状态和辨识方式。
5. **状态不只靠颜色**：选中、错误、警告和禁用状态同时使用文字、图标、边线或控件属性。

### 颜色使用约束

- 页面大面积背景只使用 `page`、`surface` 和 `surface-subtle`。`tool-surface` 只用于详情与比较的
  明确工具区域，不扩展到普通页面区块。
- 碳黑工具面在浅色和深色主题中都保持深色；其内部文字、边线、交互和焦点必须改用
  `tool-ink`、`tool-muted`、`tool-line`、`tool-accent` 和 `tool-on-accent`，不能继承浅色页面令牌。
  工具面内的风险状态固定使用 `tool-signal`、`tool-signal-ink` 和 `tool-signal-soft`。
- `accent` 不用作普通正文，也不铺满大面积页面区块。
- 选中状态使用青色侧轨或边线、文字/图标变化及必要的 `accent-soft`，不能只换底色。
- `signal` 系列只用于警告、加载/认证错误、服务不可用、比较上限和不可逆操作确认等关键
  风险语义。移除比较项、清空可恢复选择、取消收藏和退出登录等常规可恢复操作保持中性。
- “热门”“VIP”或价格标签若不是风险，不得使用橙色；它们使用中性 keyline 或青色交互语义。
- 浅色主题中 `#F28B3C` 不直接承载正文、图标或控件边界；它只能作为配合风险文字/图标的
  辅助色块或侧轨。风险文字、图标和边界使用 `signal-ink`，确保状态不依赖低对比橙色。
- 原有绿色值及 Tailwind `green`、`emerald`、`teal` 类全部移除。青色令牌不得偏绿。
- 现有红色和琥珀色类按语义逐项处理：关键风险映射到 `signal` 系列，常规可恢复操作改为
  中性，非风险状态改为中性或青色，避免机械换色和第三套竞争性色彩。

## 材质、边框与圆角

- 默认分隔使用 1px 实线 `line`；普通分组和表头使用 `line-strong`，碳黑工具面使用 `tool-line`。
- 页面区块保持无框或使用单层 keyline，不为每个区块添加悬浮卡片。
- 普通输入、按钮、行、弹窗和抽屉使用 6px 圆角；标签、状态标和小型分段项使用 4px。
- 图标按钮可使用 6px 圆角，不使用圆形或胶囊形容器，熟悉操作只显示 Lucide 图标并提供提示。
- 阴影只允许出现在搜索建议、抽屉、弹窗和固定比较托盘；阴影为中性黑色且不带彩色光晕。
- 详情决策栏、比较托盘和比较页表头在两种主题中都使用深色 `tool-surface`，通过边框和背景
  层级形成碳黑工具面。
- 深色工具面不能与页面融成一片；至少保留一条可见 keyline。

## 字体与图标

- 继续使用本地 Geist，中文回退 Arial、`PingFang SC`、`Microsoft YaHei` 和系统无衬线字体。
- 字号、字重、行高和既有标题层级保持不变，不按视口宽度缩放字号。
- 字距保持 `0`，不使用负字距、全大写装饰标签或等宽字体模拟终端。
- 数字和元数据可以使用现有 Geist 的较紧凑字重，但不创造虚构监控读数。
- 操作和状态继续使用 Lucide 图标；不手绘 SVG、不使用字符图标或装饰性电路线图标。

## 全局组件规则

### 导航与页面框架

- 顶部导航使用 `surface` 和底部 `line`，品牌文字为 `ink`，当前路由文字为 `accent-ink`。
- 当前导航项同时使用文字颜色与下边线或侧线，不使用青色胶囊。
- 主题、账户等图标按钮保持至少 44px 点击区域，悬停使用 `surface-hover`。
- 移动底部导航使用 `surface`、顶部 keyline 和安全区；当前项图标使用 `accent`，文字使用
  `accent-ink`。
- 页脚保持低对比中性，不增加发光品牌区或大面积碳黑装饰带。

### 搜索、输入与菜单

- 输入默认使用 `surface`、`line-strong` 和 `ink`；占位文字使用 `muted-subtle`。较强控件边线
  用于满足非文本边界对比，普通内容分隔仍使用 `line`。
- 悬停只改变边框，聚焦使用 2px `accent` 轮廓和 2px 外偏移，不发光、不改变尺寸。
- 搜索建议、选择菜单和筛选抽屉使用实色 `surface`、1px keyline 和克制中性阴影。
- 高亮建议使用左侧 3px 青色轨道、`accent-soft` 和清晰文字；键盘与指针状态必须一致。
- 错误输入同时显示 `signal-ink` 边线、警告图标和明确文本；`signal` 仅可作为辅助色块。

### 按钮、链接与选择控件

- 主要按钮使用 `accent` 实底；浅色主题按钮文字使用白色，深色主题按钮文字使用 `#081218`。
  碳黑工具面内改用 `tool-accent` 实底和 `tool-on-accent` 前景。
- 有描边的次要按钮使用透明或 `surface` 背景加 `line-strong`；悬停使用 `surface-hover`。
  无描边文字按钮可以不使用边界，但必须通过文字/图标清楚表达操作。工具面次按钮使用 `tool-line`。
- 只有不可逆操作的确认状态使用 `signal-ink` 文字与 `signal`/`signal-soft`；常规移除、清空、
  取消收藏和退出操作使用中性次按钮，不把橙色用于普通操作。
- 普通字号链接文字使用 `accent-ink`；`accent` 只用于其图标、下划线或控件状态。悬停增加
  下划线或颜色变化，不使用位移。
- 复选框、单选项和开关的选中控件使用 `accent`，同时保留勾选、圆点或位置变化。
- 禁用状态降低中性色对比并保留可读标签；不得只依赖透明度隐藏含义。

### 标签与状态

- 任务、来源、平台、价格等普通标签使用中性背景和 keyline，圆角 4px。
- “任务映射”可使用 `accent` 侧线或 `accent-ink` 文字；“同类工具”保持中性并保留可见文本。
- 警告、错误、服务不可用和关键上限使用 `signal-ink` 图标/边线与明确状态文案，`signal`
  只作为辅助色块或侧轨。
- 状态标签不得用发光圆点、呼吸动画或仅颜色区分。

### 加载、空态和错误

- 骨架使用 `surface-subtle` 与 `line`，不使用流动渐变或霓虹 shimmer。
- 空态保持页面结构，用中性图标、`ink` 标题、`muted` 说明和现有恢复操作。
- 错误态使用单层 `signal-ink` keyline、`signal-soft` 背景和重试操作，不覆盖静态可用信息。
- 已验证为空、加载中和加载失败必须继续以不同文字和控件状态表达。

## 页面与关键组件

### 首页 `/`

- 保留紧凑标题、搜索、8 个真实任务入口和“本周值得试”的既有顺序。
- 任务入口保持开放式列表；选中/悬停以青色侧轨、keyline 和文字变化表达。
- 工具决策行使用白色或碳黑实色面，不恢复营销卡片、插图或装饰背景。

### 工具目录 `/tools`

- `TaskContextBar`、`FilterRail` 和 `ToolDecisionList` 保持现有布局与字段顺序。
- 筛选轨道使用 `surface`/`page` 分层和右侧 keyline，不包装成浮卡。
- 每个 `ToolDecisionRow` 默认中性；悬停改变 keyline/背景，选中时显示固定 3px 青色左侧轨道。
- 青色轨道不改变行宽，必须预留空间或使用内嵌边线，避免选择时发生布局位移。
- “任务匹配/同类工具”、能力、价格、来源和平台继续用文字明确表达，不用色彩代替字段。
- `CompareTray` 使用 `tool-surface`、顶部 `tool-line`、工具面文字令牌和中性阴影；移除按钮
  保持 44px 目标。

### 工具详情 `/tools/[slug]`

- 首屏摘要和证据字段顺序不变，主操作使用青色，收藏与比较保持次操作。
- 桌面 sticky 决策栏使用 `tool-surface`、`tool-ink` 和 1px `tool-line`，形成独立但不悬浮的
  控制台工具面。
- 能力、定价、限制、标签/更新、评分和评价区以 keyline 分节，不为每节增加嵌套卡片。
- 评分的加载、错误、已验证空态继续分别展示；星级或评价操作不得改成橙色装饰。
- 替代方案继续使用紧凑决策行，并遵守相同青色侧轨和字段规则。

### 比较 `/compare`

- 保持当前字段和响应式结构，只统一为碳黑工具面、清晰列线和青色交互状态。
- 表头和固定决策区域使用 `tool-surface` 及配套工具面令牌；普通数据单元使用 `surface` 或页面底色。
- 差异不通过任意彩色热力图表达；使用文字、字重、图标和必要的青色选中状态。
- 移除与清空可恢复选择使用中性次操作；普通内容面上的比较上限和操作失败使用 `signal` 系列，
  碳黑工具面内使用 `tool-signal` 系列，并继续提供可访问反馈与焦点交接。

### 场景、排行、用户、认证和通用错误

- 不重排页面，只把原有绿色、红色和琥珀色类映射到本规范语义令牌。
- 排行“常用”、工具“热门/VIP”等非风险状态使用中性或青色样式，不占用橙色风险语义。
- 登录状态使用普通 `ink`/`muted` 文本；云同步不可用和认证错误使用 `signal` 系列，退出登录
  使用中性次按钮。
- 收藏心形可保留填充状态，但颜色使用青色；取消收藏继续通过无障碍标签和状态反馈表达。

## 交互与动效

- 颜色、背景、边框和图标状态过渡为 120–160ms，默认采用 `ease-out`。
- 不对卡片、行、按钮或图标使用缩放、弹跳、旋转、视差或悬停位移。
- 选择、加载和错误反馈不得改变固定列宽、工具栏高度、行高度或按钮尺寸。
- 抽屉和弹窗可沿用现有进入/退出行为，但不得增加彩色光带或弹性动画。
- `prefers-reduced-motion: reduce` 下将非必要过渡降至近零，保留即时状态变化。

## 响应式规则

- 保持现有桌面、平板和移动信息架构与断点，不因主题改造重排字段。
- 桌面矩阵列、筛选轨道和详情 sticky 栏保持稳定尺寸；边线不能挤压内容或造成跳动。
- 平板筛选抽屉和合并元数据继续使用相同语义令牌。
- 移动决策行保持紧凑纵向顺序，青色选中轨道位于条目左侧且不覆盖文字。
- 移动底部导航、比较托盘和安全区继续正确叠放，最后一项内容不可被遮挡。
- 320px 宽不得产生页面级横向滚动；长工具名、标签和按钮文本不得越界或互相遮挡。

## 无障碍与对比度

- 普通文本与背景达到 WCAG AA 4.5:1；大号文字和非文本控件至少 3:1。
- `muted` 和 `muted-subtle` 在规定的 `page`/`surface` 上必须达到 4.5:1；工具面文字只使用
  `tool-ink`/`tool-muted`。实施验收需再次计算实际组合，不能用青色或橙色补救不合格中性色。
- 输入、选择器、复选框等控件的可见边界使用 `line-strong`，在 `surface` 上至少达到 3:1；
  碳黑工具面内使用 `tool-line`，同样至少达到 3:1。普通装饰性分隔线可继续使用 `line`。
- 主要按钮文字需分别在浅色与深色 `accent` 上验证；不得全局固定为白色。浅色普通字号链接
  使用 `accent-ink`，不在 `page` 上直接使用 `accent` 作为链接文字。
- 碳黑工具面主按钮使用 `tool-on-accent`/`tool-accent`，风险状态使用
  `tool-signal-ink`/`tool-signal-soft`；两组正文组合均达到 4.5:1，可见控件边界达到 3:1。
- 2px 青色 `:focus-visible` 轮廓保留 2px 外偏移；普通页面使用 `accent`，碳黑工具面使用
  `tool-accent`，在各自相邻背景上均需达到 3:1。
- 选中行同时提供侧轨、控件选中状态和可访问属性；风险状态同时提供图标和文字。
- 所有主要操作、图标按钮、移除操作和移动控件保持至少 44×44px 目标。
- 搜索列表保持组合框语义、键盘导航、指针选择和可见活动项；主题不得降低活动项对比。

## 实现边界

主题实现应优先集中在全局语义令牌和共享组件，避免逐页面硬编码。预计修改范围包括：

- `next-src/src/app/globals.css` 和 `next-src/src/app/layout.tsx` 的主题颜色元数据。
- 导航、底部导航、页脚、搜索、筛选和通用输入/按钮。
- 决策行、详情摘要/证据、比较托盘和比较页面。
- 场景、排行、用户、认证、工具卡片和错误边界中的旧绿色/红色/琥珀色状态类。
- 与主题令牌、禁用颜色和不允许的装饰效果相关的契约测试及浏览器守卫。

实现不得修改工具 JSON、Supabase、API、Zustand 业务状态、URL 参数、路由或现有交互合约。

## 测试与设计 QA

### 静态与契约检查

- 扫描 `next-src/src`，不得残留旧灰绿十六进制值或 Tailwind `green`、`emerald`、`teal` 类。
- 扫描不得新增渐变、彩色 glow、装饰网格、扫描线、缩放或位移动画。
- 验证浅色/深色语义令牌完整，主题切换不改变组件尺寸和布局。
- 保留任务优先 UI、数据加载、搜索、评分和比较交互的现有契约测试。

### 浏览器验收

检查路由：`/`、`/tools?scene=research`、一个工具详情、`/compare`、`/scenes`、
`/leaderboard`、`/user` 和认证弹窗。

检查视口：`1440x900`、`1280x720`、`768x1024`、`390x844` 和 `320x700`。
每个核心路由至少检查浅色和深色主题，并验证：

- 页面没有绿色、渐变、光晕、装饰网格或灰绿残留。
- 青色和橙色遵循各自语义，没有大面积彩色铺底。
- 页面层级、keyline、碳黑工具面和当前/选中状态清晰。
- 文本对比度、焦点轮廓、键盘路径和 44px 目标合格。
- 没有横向溢出、文本遮挡、固定栏遮挡、布局位移或控制台错误。
- 浅色与深色截图的结构、行列位置和内容顺序一致。

设计 QA 使用相同视口对照当前已批准截图。对照只判断布局、密度、内容和交互状态是否保持；
颜色和材质以本规范为唯一基准。
